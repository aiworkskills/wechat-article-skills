# 一条龙的分支与补充规则

SKILL.md 只写主路径：配置自检 → 全局约束 → 本篇准备 → 内容流水线 → 发布。本文件是**走不到主路径时才读的东西**，主路径在对应位置用一行指过来。

---

## 一、B 分支：我已有目录

用户直接给出 `drafts/…` 路径时走这条，不必从「新建一篇」开始。

- 必读 `.aws-article/config.yaml`（账号与发布策略）；本篇目录内需有 `article.yaml`（或按用户状态后补）。
- 若已有 `article.html` / `cover.*`，可直接从流水线中靠后的步骤接入，不必重跑前面的环节。
- 若用户意图是「发布后换图并重发草稿箱」，也走本分支——指定既有目录后，从**配图的用户供图分支**接入，再执行终审 → 发布。详见下面第二节。

---

## 二、发布后换图重发

用户说「草稿箱里图不满意，换我上传的图重新发」时：

1. 锁定目标 `drafts/…` 目录。
2. 新图放入本篇 `imgs/`，生成或更新 `img_analysis.md`（**封面仅 1 张**）；同步把 `article.yaml` 的 `image_source` 改为 `user`，并把 `publish_completed` **置回 `false`**。
3. 依据分析结果更新 `article.md` 的图片映射（允许重排章节以匹配图序）。
4. **重新执行 `format.py` 生成整份 `article.html`**，不要只改旧 HTML 的局部。
5. 终审通过后执行 `publish.py full`（`publish_method: draft` 时写入草稿箱）。
6. 发布命令成功且回执可用后，才写回 `publish_completed: true`。

配图侧的对应细则见 [images 的 branches.md](../../aws-wechat-article-images/references/branches.md)。

## 三、`validate_env.py` 退出码 1（微信配置不完整）

**只展示** [首次引导](first-time-setup.md) 里的配置选项，**不要**在同一轮回复里再问「写哪篇 / 继续哪篇草稿 / 新选题」。

须等配置闭环——重跑校验通过，或用户书面确认「本次例外」——**之后**才进入「全局账号约束」。

用户明确不接微信时，可设 `publish_method: none` 后重跑校验。

完整的失败引导文案与行为约束（禁止自作主张、不得索取密钥）见 [首次引导](first-time-setup.md)。

---

## 四、全局三键为空时怎么问 ⛔

`article_category` / `target_reader` / `default_author` 任一为空时**逐项询问用户**（1. 账号领域 2. 目标读者 3. 作者名字），取得**当轮明确答复**后**写回** `.aws-article/config.yaml`。

**禁止只在对话里口头确认却不写入文件**，也禁止跳过本步直接假定可写稿。

**禁止擅自填写**：不得从本篇或其它目录的 `article.yaml`、历史草稿、`topic-card.md`、对话记忆或仓库内任意文件**静默抄录、推断或「顺手补全」**。对 `tone` 等与账号画像强相关的全局项同样如此。

**允许的做法**：说明「当前为空」，请用户填写或确认；想根据某篇 `article.yaml` 给建议，只能**展示为待选文案**并问「是否采用 / 要改哪几个字」，用户明确同意后再写入。

**顺序**：在尚未完成「续旧 / 新开」的确认前，**禁止**用某一 `drafts/…/article.yaml` 反推全局三键——那会把单篇元数据当成整号定位。

---

## 五、续写 / 重入时的预设处理

本篇 `article.yaml` 里对应字段**已是单元素列表**时，视为本篇已选，**优先保留，不重选不覆盖**。

`config.yaml` 不存在或候选为空时，保持 `[]`。

---

## 六、单步子 skill

用户只触发某一子能力（如仅排版、仅审稿）且**未走本总览流水线**时，仍以各子 skill 内的说明为准。

**一条龙 / 完整流程 / 从选题到发布**必须满足 SKILL.md 的 BLOCKING 规则与首次引导里的行为约束。

表述含糊、可能还要后续发文时，仍从 main 问起或按一条龙拆步确认。
