# 正文配图推导方法

封面抢点击，正文配图帮阅读。这份是正文配图的流程，封面走 [cover-method.md](cover-method.md)。

输入：`article.md` 里的一个配图标记 + 文章上下文 + 候选形态池（`custom_article_image_style`，默认全选）。
输出：一个 prompt 文件（frontmatter `aspect: "16:9"`），或者**判定这里不需要图**。

---

## 第一步：先问要不要这张图

**删掉它，读者会「看不懂」还是「读不下去」？**

| 答案 | 结论 |
|---|---|
| 看不懂 | **信息位**，必须留，且必须带文章真实内容 |
| 读不下去 | **节奏位**，可留可换，纯粹给眼睛休息 |
| 都不影响 | **删掉这个图位** |

第三种要真的删。无信息量的氛围图会稀释信息密度，让读者划得更快、退出更早——排版的目的是降低阅读成本，不是填满页面。

writing 阶段插入的标记（`![信息图：…]`、`![流程图：…]`、`![插图：…]`、`![对比：…]`）只是提示，不是命令。标记说要图但这里三条都不占，就删掉它。

标记的数量由 writing 阶段按 config `image_density` 决定：

| `image_density` | 规则 |
|---|---|
| 每节一图 | 每个 H2 小标题后一张 |
| 按需配图 | 只在讲不清的地方放 |
| 少图 | 仅封面 + 1–2 张关键配图 |
| 多图 | 每 2–3 段一张 |

images 阶段按标记执行，但**有权删掉不占三条中任何一条的图位**。

## 第二步：选形态

从候选池里挑。标记类型给了初始方向，但以内容为准：

| 这段在讲 | 形态 | 位 |
|---|---|---|
| 操作顺序、方法步骤 | 流程步骤 | 信息位 |
| 系统构成、层级关系 | 结构分层 | 信息位 |
| 数字、趋势、指标 | 数据图表 | 信息位 |
| 前后差异、方案取舍 | 对比两栏 | 信息位 |
| 并列要点、检查项 | 清单要点 | 信息位 |
| 抽象概念、观点 | 概念隐喻 | 节奏位 |
| 使用场景、代入感 | 场景还原 | 节奏位 |
| 章节转折、情绪停顿 | 氛围留白 | 节奏位 |
| 边想边讲、思路推演 | 手绘草图 | 中间 |

## 第三步：取真实内容（信息位必做）

**信息位的每一个字都必须来自文章，不能让模型自由发挥。**

从这张图所在的那一段及前后文里，抄出真实的：步骤名、层级名、数值与单位、对比项、要点句。写进 prompt 时逐字给出。

实测：让模型自己填清单内容，它会生成「保持高效工作状态」「享受生活每一刻」这类与文章无关的鸡汤，还自带 emoji。

节奏位跳过这步——它不承载信息。

## 第四步：定媒介（每篇一次）

**这一步在生成任何图之前做，一篇文章只做一次，本篇所有信息位配图共用同一个媒介。**

信息位的图默认是扁平矢量——圆角矩形、箭头、低饱和色块。那正是全世界 AI 信息图的默认长相，任何文章配上都像模板。实测同样四个步骤、同样信息量，换成手绘媒介后 AI 味基本消失，而且步骤名更好读（因为去掉了没人看的说明小字）。

关键在这些媒介自带**不完美的痕迹**：擦不净的旧字迹、翘边的便签、洇开的墨点、涂改和批注。扁平矢量的完美恰恰是 AI 味的来源。

| 媒介 | 长什么样 | 适合 |
|---|---|---|
| **马克笔白板** | 磁性白板、金属边框、手写行楷、红笔圈注、旧字迹残影 | 讲解、流程、对比。像刚开完会 |
| **方格笔记本** | 格子纸、钢笔手绘、墨迹洇开、涂改、红笔波浪线 | 结构、图表、需要对齐的内容 |
| **便签手写** | 彩色便签贴在木桌上、翘边投影、签字笔字迹 | 清单、要点、思路整理 |
| **黑板粉笔** | 深绿黑板、粉笔字、擦痕 | 教学、科普、课堂感 |
| **扁平矢量** | 圆角矩形、箭头、低饱和色块 | 产品文档风的科技号、需要精确对齐的架构图 |

**怎么选**：按 config 的 `tone` 与 `account_type` 推理，不要随机。

- 犀利、极客、口语化 → 白板 / 便签
- 温暖、个人向、随笔 → 方格笔记本 / 便签
- 严谨、财经、To B、产品文档 → 扁平矢量
- 教育、科普 → 黑板粉笔 / 白板

**同一篇文章内必须统一。** 三张配图分别是白板、便签、笔记本，读起来像三个人做的。跨文章可以换——跨篇一致性本来就不需要。

节奏位（概念隐喻 / 场景还原 / 氛围留白）不受这条约束，它们本来就不是示意图。

## 第五步：套模板与维度

照抄该形态模板的五个字段：主体、影调、**文案**、版式。文案规格（有无字、字号、位置）一字不改。

从「可轮换维度」里各选一个值。**同一篇文章内的多张配图必须错开维度组合**——一篇文章连着三张流程图都用同样的方向、格数、配色，读者会觉得在重复看同一张。

## 第六步：写成 prompt

`aspect: "16:9"`，正文宽 1080px。

正文配图的信息密度**可以比封面高**——允许文字与细节，目的是辅助理解，不是三秒抢眼球。

一条硬经验：**负向指令压不住模型的默认形态**。清单、卡片这类版式在训练分布里绑定了「卡片阴影 + emoji + 说明小字」，写「不要 emoji」「不要卡片」无效。必须正面描述一个不含这些元素的具体画面：

> 纯米白色背景，整幅画面没有任何纸张、卡片、阴影或边框，背景与画布融为一体。
> 画面上除了这四个数字和四行中文，没有别的任何图形、符号、图标或文字。

## 第七步：回看

打开生成的图，对四条：

1. 中文有没有错字，信息位的内容是不是文章里的真实内容（不是模型编的）
2. 有没有混进 emoji、英文标点、多余的说明小字
3. 手机上占满屏宽时能不能读清
4. 和这一段文字是不是真的相关

不过关回到出问题的那一步：内容错了回第三步，AI 味重回第四步换媒介，混进杂物回第六步换正面描述，形态不对回第二步。
