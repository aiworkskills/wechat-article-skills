# 正文配图推导方法

封面抢点击，正文配图帮阅读。这份是正文配图的流程，封面走 [cover-method.md](cover-method.md)。

输入：`article.md` 里的一个配图标记 + 文章上下文 + 候选形态池（`custom_article_image_style`，默认全选）。
输出：一个 prompt 文件（frontmatter `aspect: "16:9"`），或者**判定这里不需要图**。

---

## 第一步：先问要不要这张图

**删掉它，读者会「看不懂」还是「读不下去」？**

| 答案 | 结论 |
|---|---|
| 看不懂 | **信息位**，必须留，且必须带文章真实内容 |
| 读不下去 | **节奏位**，可留可换，纯粹给眼睛休息 |
| 都不影响 | **候选删除**，但受下面的上限约束 |

无信息量的氛围图会稀释信息密度，让读者划得更快、退出更早——排版的目的是降低阅读成本，不是填满页面。

标记的数量由 writing 阶段按 config `image_density` 决定。**这张表与 `write.py` 的 `_DENSITY_RULES`、[writing SKILL 第 4 条](../../aws-wechat-article-writing/SKILL.md) 是同一套定义，措辞须一致：**

| `image_density` | 就是说 |
|---|---|
| 每节一图 | 每个 `##` 小节各配一张，不多不少 |
| 按需配图 | 只在文字讲不清的地方配（流程、对比、数据），其余不配 |
| 少图 | 全篇只配 1–2 张最关键的 |
| 多图 | 每 2–3 个自然段配一张 |

### 删除上限 ⛔

**每篇最多删 1 个图位，且必须在结果里写明删了哪个、为什么。**

这条是补上来的：删除权原本没有下限，配上「标记只是提示不是命令」这句，实际结果是配了「每节一图」的号，五篇稿子出来的正文图每篇都比小节数少。写稿阶段已经欠了一次（模型本来就少产），配图阶段再删一次，两次相减读者那边就只剩两三张图。

**判定要删 2 个以上时不要自行删**——那说明 `image_density` 和这篇的内容对不上，应当把这个判断告诉用户（「本篇配的是每节一图，但第 3、5 节属于纯观点段落，配图只能是氛围图，建议本篇按需配图」），由用户决定改配置还是照配。自行删掉的结果是用户按配置期待 5 张、拿到 2 张，而且不知道为什么。

## 第一步半：这个图位该用图，还是用组件？⛔

排版侧有[版式组件](../../aws-wechat-article-formatting/references/components/)，
能把内容排成设计过的 HTML 块。它和信息位配图干的是同一件事，**必须先分工，
否则同一份内容会既做成卡片又画成图**——实测踩过：一篇文章里 62.7/99.9 这组数字
出现了三次（数据卡 + 对比配图 + 对比组件）。

判据只有一条：

> **内容里有没有空间关系？**
>
> 有大小、流向、嵌套、位置 → **用图**
> 只是文字并列、对照、枚举 → **用组件**

**但先看清楚哪些组件真的够得到。** 判据下面还有一层现实约束：写作侧只产出标准
markdown，`:::` 私有块语法是明令禁止的，所以**只有能被标准 markdown 触发的组件
才存在**。判给一个够不到的组件，等于图也删了、组件也没有，那段内容的视觉表达直接
消失——这是踩过的坑，不是假设。

| 形态 | 归谁 | 为什么 |
|---|---|---|
| 数据图表 | **图** | 柱子高低直接表达大小关系，卡片只能把数字列出来让读者自己比 |
| 流程步骤 | **图** | 箭头表达「流向」；组件的竖线只表达「这几条是一组」 |
| 结构分层 | **图** | 大括号和嵌套是空间关系，组件只能平铺成几行 |
| 对比两栏 | **图** | `compare` 组件只有 `:::` 一条路，写作侧够不到。判给它就是两头落空 |
| 清单要点 | **图** | 同上：`checklist` 块够不到；`- [ ]` 任务列表是低频写法，不能指望它出现 |
| 金句卡片 | **组件** | `> 金句。 —— 出处` 是标准 markdown，写作侧有硬配额保证每篇出现一次 |

**注意「数字 → 组件」是错的。** 数据图表恰恰全是数字，却是图赢得最彻底的一项——
决定因素是有没有大小关系要看，不是内容是不是数字。

**金句卡片是唯一要防重复的一项**：写作侧每篇恰好产出一处 `> 金句。 —— 出处`，
排版会把它排成金句卡。再为它画一张「金句卡片」配图，同一句话会出现两次。

组件的其余优势（顺带）：文字可搜索可复制、改一个数只改一行、自动继承主题色、
不会出现分辨率不足和 AI 味。但**判不准的时候优先图**——组件够不到就是彻底没有，
而多一张图只是多花一点钱。

## 第二步：选形态

从候选池里挑。标记类型给了初始方向，但以内容为准：

| 这段在讲 | 形态 | 位 |
|---|---|---|
| 操作顺序、方法步骤 | 流程步骤 | 信息位 |
| 系统构成、层级关系 | 结构分层 | 信息位 |
| 数字、趋势、指标 | 数据图表 | 信息位 |
| 前后差异、方案取舍 | 对比两栏 | 信息位 |
| 并列要点、检查项 | 清单要点 | 信息位 |
| 抽象概念、观点 | 概念隐喻 | 节奏位 |
| 使用场景、代入感 | 场景还原 | 节奏位 |
| 全文最值得单独记住的一句 | 金句卡片 | 节奏位 |

「手绘」不是形态，是**媒介**（第四步）——任何信息位形态都能用手绘画出来，它不该和流程步骤并列成为二选一。

## 第三步：取真实内容（信息位必做）

**信息位的每一个字都必须来自文章，不能让模型自由发挥。**

从这张图所在的那一段及前后文里，抄出真实的：步骤名、层级名、数值与单位、对比项、要点句。写进 prompt 时逐字给出。

实测：让模型自己填清单内容，它会生成「保持高效工作状态」「享受生活每一刻」这类与文章无关的鸡汤，还自带 emoji。

节奏位跳过这步——它不承载信息。

## 第四步：定媒介（每篇一次，按本篇内容定）

**这一步在生成任何图之前做，一篇文章只做一次，本篇所有信息位配图共用同一个媒介。**

信息位的图默认是扁平矢量——圆角矩形、箭头、低饱和色块。那正是全世界 AI 信息图的默认长相，任何文章配上都像模板。

**为什么换个媒介就没有 AI 味了？** 一开始的解释是「手绘自带不完美的痕迹」，这个说法不对。实测把同样内容画成**终端窗口**——等宽字、纯色底、像素级整齐，一点不完美都没有——照样零 AI 味。

真正的原因是：**白板、牛皮纸、黑板、终端、批注过的打印稿，都是读者在生活里真见过的载体。** 而「扁平矢量信息图」不是任何人会遇到的实物，它只是一个模板。读者认得出前者是有人做的东西，认不出后者是什么。

### 媒介池

| 媒介 | 长什么样 | 适合 |
|---|---|---|
| **马克笔白板** | 磁性白板、金属边框、手写行楷、红笔圈注、旧字迹残影 | 讲解、流程、对比。像刚开完会 |
| **方格笔记本** | 格子纸、钢笔手绘、墨迹洇开、涂改、红笔波浪线 | 结构、图表、需要对齐的内容 |
| **便签手写** | 彩色便签贴在木桌上、翘边投影、签字笔字迹 | 清单、要点、思路整理 |
| **黑板粉笔** | 深墨绿黑板、粉笔飞白、云雾状旧擦痕、槽里的粉笔头与板擦 | 教学、科普、课堂感 |
| **牛皮纸圆珠笔** | 牛皮纸折痕、蓝黑圆珠笔、划掉重写、咖啡渍 | 随笔、清单、个人向 |
| **终端等宽** | 深色终端窗、等宽字、青色正文 + 橙色提示行、方块光标 | 开发者号、命令行/配置类内容 |
| **打印稿批注** | A4 印刷体 + 红笔圈划、页边手写批注与箭头、卷边 | 拆解、评测、逐条挑毛病 |
| **扁平矢量** | 圆角矩形、箭头、低饱和色块 | 只用于 To B / 产品文档风的号。这是 AI 味的默认值，别的场合别选 |

### 怎么选：内容先定，重复才避

**媒介由本篇内容决定。** `tone` 只用来否决明显不搭的，避开上一篇只在平手时才起作用。

#### 第一顺位：按本篇讲的是什么来选 ⛔

| 本篇主要在讲 | 媒介 |
|---|---|
| 命令行、配置、报错、代码 | **终端等宽** |
| 逐条挑毛病、评测拆解、审稿 | **打印稿批注** |
| 流程、方法讲解、开会感 | **马克笔白板** |
| 清单、要点、思路整理 | **便签手写** |
| 结构、层级、需要对齐的图表 | **方格笔记本** |
| 教学、科普、入门 | **黑板粉笔** |
| 随笔、个人经历、心得 | **牛皮纸圆珠笔** |
| To B 产品文档、企业向 | **扁平矢量** |

#### 第二顺位：`tone` 否决

`tone` / `account_type` 只用来**排除明显违和的**（严肃财经号不要黑板粉笔，个人随笔号不要扁平矢量）。它不圈定范围、不直接决定用哪个——`tone` 是账号级、永远不变的，让它决定媒介就等于每篇都一样。

#### 第三顺位：平手才避开上一篇

**只有当两个媒介同样合适时**（比如本篇既像流程讲解又像要点整理），才看上一篇用了什么，选另一个。

**只避开上一篇，不是最近三篇。** 这条是改过的，原来写的是「从集合里排除最近 3 篇用过的」——而按 `tone` 圈出来的集合只有三四个，排除 3 个之后恒定只剩 1 个候选，「挑与本篇内容最搭的那个」永远无事可做。窗口和集合同一个量级，硬排除必然把选择权全部交给顺序，媒介退化成一个固定循环，和文章内容零关系。

**内容明确指向某个媒介时不要为了避重复而换。** 一篇讲命令行的文章配白板，比连着两篇终端窗更糟——读者认得出图和内容不搭，认不出你在轮换。

#### 记录 ⛔

**本篇选定后必须立刻写进 `article.yaml` 的 `image_medium`**，配图步骤收尾时核对这一行非空。

这一步原来只是一句口头约定，没有任何校验——实测 45 份 `article.yaml` 里 44 份是 `image_medium: ''`，等于第三顺位查到的永远是空，避重复根本没在跑。

```bash
grep -h "^image_medium:" $(ls -d drafts/*/ | sort -r | head -2 | sed 's#$#article.yaml#') 2>/dev/null
```

### 同一篇内必须统一

三张配图分别是白板、便签、笔记本，读起来像三个人做的。**篇内必须统一**：本篇所有信息位配图共用第四步定下的那一个媒介，不许一图一个样。

篇间不强制换——换不换由内容决定（见上文第三顺位）。选题本来就在变，媒介跟着内容走，跨文章的变化自然会有；靠规则强行轮换只会把不搭的媒介按到文章头上。

节奏位（概念隐喻 / 场景还原 / 金句卡片）不受这条约束，它们本来就不是示意图。

## 第五步：套模板与维度

照抄该形态模板的五个字段：主体、影调、**文案**、版式。文案规格（有无字、字号、位置）一字不改。

从「可轮换维度」里各选一个值。**同一篇文章内的多张配图必须错开维度组合**——一篇文章连着三张流程图都用同样的方向、格数、配色，读者会觉得在重复看同一张。

## 第六步：写成 prompt

`aspect: "16:9"`，正文宽 1080px。

正文配图的信息密度**可以比封面高**——允许文字与细节，目的是辅助理解，不是三秒抢眼球。

一条硬经验：**负向指令压不住模型的默认形态**。清单、卡片这类版式在训练分布里绑定了「卡片阴影 + emoji + 说明小字」，写「不要 emoji」「不要卡片」无效。必须正面描述一个不含这些元素的具体画面：

> 纯米白色背景，整幅画面没有任何纸张、卡片、阴影或边框，背景与画布融为一体。
> 画面上除了这四个数字和四行中文，没有别的任何图形、符号、图标或文字。

## 第七步：回看

打开生成的图，对四条：

1. 中文有没有错字，信息位的内容是不是文章里的真实内容（不是模型编的）
2. 有没有混进 emoji、英文标点、多余的说明小字
3. 手机上占满屏宽时能不能读清
4. 和这一段文字是不是真的相关

不过关回到出问题的那一步：内容错了回第三步，AI 味重回第四步换媒介，混进杂物回第六步换正面描述，形态不对回第二步。
